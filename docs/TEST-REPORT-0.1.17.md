# Итоговая проверка RED_ROUTE 0.1.17

Даты: 24–25 октября 2026. Продолжение [живой проверки 0.1.16](TEST-REPORT-0.1.16.md).

## Последняя найденная ошибка

Проверка маршрутов обычным TCP/TLS-клиентом первоначально начинала запросы сразу после открытия health-порта временного ядра. Запросы получали ответы, но отсутствовали в журнале TUN, тогда как позже выполненные браузерные запросы присутствовали. До проверки порядка запуска это не считалось подтверждением правильной маршрутизации.

Причина установлена контрольным повтором: открытый health-порт ещё не означает завершённую настройку TUN. После ожидания сообщения ядра о полном запуске тот же клиент получил локальный адрес TUN, выбранный домен — FakeIP, а журнал подтвердил `route(vpn)` и `outbound/direct[direct]` для выбранного и невыбранного сайта. Оба TCP/TLS-запроса завершились HTTP 200 с обычной проверкой сертификатов.

Служба использовала тот же преждевременный критерий порта. В 0.1.17 ядро redroute7 передаёт отдельную фиксированную строку `RED_ROUTE_READY` после успешного завершения всех стадий Box.Start. Служба и изолированный стенд ожидают этот сигнал; порт и последующая проверка HTTPS остаются дополнительными проверками. Сигнал не зависит от уровня журнала и не содержит адресов или ключей. Запуск ограничен 15-секундным ожиданием готовности и отменяется при отмене операции.

## Выполненные проверки

К существующим проверкам 0.1.16 добавлены отрицательный контроль уже открытого TCP-порта, строгое распознавание полного сигнала, отмена ожидания и получение сигнала от настоящего ядра для всех WG/AWG-сценариев стенда. Живая приёмка теперь требует, чтобы первое реальное IPv4 TCP-соединение после «подключено» использовало адрес TUN, а не только совпадало по внешнему IP.

- 548 автоматических проверок C# и настоящего зашифрованного WG/AWG-стенда прошли. Включены сигнал готовности реального ядра, отказ и восстановление IPv6 при работающем IPv4, отмена запуска и защита конфигурации от строкового представления в интерфейсе.
- 122 сценария предварительного маршрутизатора прошли для TCP и UDP по 100 повторов: 24 400 вызовов. Go-проверки кеша, FakeIP, маршрутизатора, AWG-пакетов, handshake и конкурентной работы прошли.
- Сборка и 18 проверок MSI прошли. Реальное обновление 0.1.16 → 0.1.17 завершилось кодом 0. Установлены приложение и служба 0.1.17, ядро redroute7.
- Все 25 живых проверок установленной 0.1.17 прошли: «Выкл», «Вкл», пустое «Авто», выбранный/невыбранный домен, IP-правило, резерв, отказ всех профилей, авария ядра и службы, автоматическое восстановление, быстрые переключения и команда восстановления интернета. Первое TCP-соединение после статуса «подключено» использовало адрес TUN.
- Все 11 дополнительных проверок прошли: три повторных аварии установленного ядра сохранили работоспособность ранее выданного DNS-адреса и курсор выделения FakeIP.
- 25 октября повторно прошёл WPF smoke-тест 0.1.17: ввод и нормализация домена, подсказки/полный каталог, прокрутка, стилизованные диалоги, скрытие в трей и повторное открытие. Отрицательный контроль завершился ожидаемым кодом 1, основной прогон — кодом 0. Тест не отправлял службе сетевых команд.

25 октября на установленной 0.1.17 повторена проверка одних и тех же вкладок Chrome. В «Авто» и «Выкл» Музыка загружает обычный интерфейс, 4PDA — страницу новостей. В «Вкл» 4PDA также загружается, Музыка отвечает сообщением о недоступности в регионе. Ошибки `ERR_CONNECTION_RESET` не повторились. Подписка не оформлялась, воспроизведение трека не подтверждено. После прогона автоматический обработчик восстановил исходные «Авто» и пользовательский файл настроек побайтно; журнал — `artifacts/checks/browser-0.1.17.log`.

Проверка повторного запуска показала штатное уведомление, что RED_ROUTE уже работает; вторая копия интерфейса не запустилась. Выход через пункт трея «Выключить VPN и выйти» остаётся непроверенным вручную: инструмент управления не смог получить доступ к свёрнутому окну/значку. Отключение через IPC, скрытие в трей и повторное открытие в WPF smoke не считаются заменой этой проверки.

Независимая сборка GitHub Actions для коммита `07fc057` завершилась успешно: [прогон 40123930937](https://github.com/cveloy102/RED_ROUTE/actions/runs/40123930937). Пройдены сборка ядра, сборка/тесты/упаковка, проверка достижимых Go-уязвимостей и WPF smoke.

## Сохранность настроек

Перед паузой и после её завершения служба находилась в «Авто / подключено». Итоговая проверка 25 октября: машинные настройки совпадают с защищённым исходным снимком, пользовательские настройки совпадают после расшифровки, сохранены один профиль и восемь правил. Зашифрованные байты пользовательского файла после запуска интерфейса отличаются; это не изменение содержимого настроек. Самопроизвольных перестроек сети в проверенном журнале не обнаружено. Работает один установленный процесс ядра; временных диагностических конфигураций не осталось.

Локальные материалы: `artifacts/checks/build-0.1.17.log`, `package-0.1.17.log`, `install-0.1.17.log`, `live-acceptance-0.1.17.json`, `cached-dns-regression-0.1.17.json`, `restored-0.1.17.json`. Они не включаются в публичный репозиторий. Установочная сборка создана до коммита этих изменений и содержит прежний информационный Git SHA; функционально проверена именно локальная сборка 0.1.17 с redroute7.

## Сохранённые ограничения

Маршруты ChatGPT на роутере сохраняются для связи; роутер и OpenVPN агент не меняет. Проверки внешнего IP дополняются реальным выбором маршрута по журналу ядра. Полноценное воспроизведение Музыки не подтверждено из-за предложения оформить Плюс; в полном VPN сайт отвечает региональным ограничением, а в «Авто» и «Выкл» загружает обычный интерфейс.

Чистые Windows 10/11, физическая смена сети, сон/пробуждение, перезагрузка, другая учётная запись UAC и два независимых реальных резервных сервера остаются отдельной приёмкой. Рабочий внешний IPv6 проверяется положительно на изолированном стенде; текущий VPN-профиль объявляет IPv6, но реальные IPv6-пробы через сервер не проходят.
