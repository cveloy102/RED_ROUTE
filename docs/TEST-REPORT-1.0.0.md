# Проверка RED_ROUTE 1.0.0

Дата: 26 октября 2026. Продолжение [проверки 0.1.17](TEST-REPORT-0.1.17.md).

## Оформление

Добавлены System/Light/Dark, отдельное пользовательское хранилище `appearance.json`, чтение темы приложений Windows и реакция на системное уведомление об изменении оформления. Настройки VPN, IPC и служба при выборе темы не вызываются. При отсутствии или повреждении предпочтения выбирается System. Сохранение атомарное; ошибка записи оставляет предыдущее предпочтение.

Цвета окон, заголовков, режимов, подсказок, каретки, выделения, прокрутки, диалогов, обновления и установщика вынесены в общую палитру. Главному окну явно назначен стиль Window: неявный стиль базового типа не применялся автоматически к производному MainWindow. Меню WinForms получило свой renderer, согласованный с палитрой; его иконки учитывают выбранную тему, значок панели задач — SystemUsesLightTheme Windows.

Пройдены WPF smoke-прогоны отдельно для Light и Dark: нормализация/отбраковка доменов, каталог/подсказки/выбор сервиса, прокрутка страницы и каталога, расширенный режим, диалоги импорта/удаления/обновления, скрытие и повторное открытие. Дополнительно проверены переключение существующего окна, сохранение/повторное чтение темы, повреждённый JSON и разрешение System при обеих системных темах. Отрицательный контроль завершился ожидаемым кодом 1. Установщик отрисован в Light/Dark на этапах welcome/progress/success без запуска установки в этих preview-прогонах.

В установленной 1.0.0 вручную выбрана Light и затем System: окно сразу меняет палитру. Системные параметры Windows агент не изменял; реальный системный переход темы при открытом приложении не воспроизводился.

## Автоматические и живые проверки

- 554 проверки C# и настоящего зашифрованного WG/AWG-стенда прошли, включая IPv4/IPv6, отказ/восстановление, DNS-кеш, IPC, хранилище и распознавание VPN-адаптеров.
- Матрица предварительного маршрутизатора: 122 сценария, TCP/UDP по 100 повторов — 24 400 вызовов.
- 18 проверок MSI прошли. Обновление 0.1.17 → пробная 1.0.0 завершилось кодом 0.
- Перед окончательной установкой пробная сборка 1.0.0 удалена штатным MSI (код 0), финальная установлена заново (код 0). Проверены побайтная сохранность машинного и пользовательского DPAPI-файлов и `appearance.json`, прежний владелец службы, ровно одна запись приложения в списке установленных программ. Обычное обновление с предыдущей версии проверено отдельно; переустановка нужна была только для замены неопубликованной сборки с тем же номером.
- Все 25 живых проверок установленной 1.0.0 прошли: режимы, выбранный/невыбранный домен, IP-правило, первый TCP через TUN, резерв, недоступные серверы, аварии ядра/службы, автоматическое восстановление, быстрые переключения и сохранность настроек. По завершении восстановлено исходное «Выкл», один профиль и восемь правил.
- Повторная упаковка выявила отсутствие явной загрузки System.IO.Compression.FileSystem в Windows PowerShell 5.1. Исправлен сборочный сценарий; окончательная сборка под PowerShell 7 завершилась полностью, включая архив соответствующих исходников ядра.

## Совместная работа с AmneziaWG

Пользователь включил существующий BRO_2. Настройки и профиль другого клиента агент не менял.

| RED_ROUTE | Результат при работающем BRO_2 |
| --- | --- |
| Выкл, до проверки | Оба публичных тестовых адреса доступны; BRO_2 Up |
| Авто | За 50 секунд нет Connected; HTTPS-пробы VPN завершаются тайм-аутом. Оба адреса доступны через прежний выход BRO_2 |
| Вкл | За 50 секунд нет Connected; обе версии HTTPS-проб завершаются тайм-аутом. Интернет остаётся через BRO_2 |
| Возврат в Выкл | Оба адреса доступны; BRO_2 остаётся Up |

В журнале сохраняются только хеши публичных выходов для сравнения. Это подтверждённая несовместимость данных двух подключений, а не доказательство несовместимости со всеми VPN. Конкретная причина между маршрутами и WFP-фильтрами не изолирована. Официальная [документация AmneziaWG](https://github.com/amnezia-vpn/amneziawg-windows-client/blob/master/docs/netquirk.md) описывает дополнительную фильтрацию при полном маршруте `/0`; наличие именно этих фильтров в BRO_2 отдельно не подтверждалось. Попытка прочитать только AllowedIPs штатной CLI была неуспешной; ключи и конфигурация не выводились.

После выключения BRO_2 пользователем RED_ROUTE самостоятельно подключился: HTTPS 204, состояние Connected сохранилось через 12 секунд; затем восстановлено «Выкл». Внешний IP совпал с исходным, поэтому этот отдельный повтор не используется как доказательство выбора маршрута — для этого служат первая TCP/TUN-проверка живой приёмки и ранее зафиксированный коррелированный журнал ядра.

В приложение добавлено информационное уведомление о распознанном другом активном VPN. Это эвристика по драйверу активного адаптера, а не полный детектор VPN или kill-switch; она ничего не блокирует и не отключает. Проверены исключение RED_ROUTE, обычного Ethernet и ISATAP, а также распознавание WireGuard, OpenVPN DCO и TAP.

## Границы проверки

Чистые установки Windows 10/11, реальный сон/пробуждение, перезагрузка, физическая смена сети и повышение прав из другой учётной записи не проверены. Восстановление службы после аварии и изменение сетевых возможностей проверены отдельно; это не заменяет сон и перезагрузку. Резервный профиль проверен недоступной копией и рабочим сервером, а не двумя независимыми действующими серверами. Ручной выход через значок трея не подтверждён инструментом управления; скрытие/повторное открытие и команда восстановления проверены отдельно.

Локальные материалы в игнорируемом `artifacts/`: `checks/build-1.0.0-final.log`, `checks/ui-1.0.0-final.log`, `checks/live-acceptance-1.0.0.json`, `checks/coexistence-1.0.0.log`, `coexistence/result.json`, `checks/post-bro2-1.0.0.log` и `ui/light`, `ui/dark`, `ui/setup-light`, `ui/setup-dark`. Пользовательские данные, ключи и полные установочные журналы не публикуются.
