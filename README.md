# RED_ROUTE

Нативный VPN-клиент для **Windows 10 22H2 / Windows 11 x64**. C# / .NET 10 / WPF,
служба Windows и встроенное официальное ядро Amnezia. Название режима всегда
сопровождается объяснением.

- **Вкл** — весь публичный интернет через VPN; локальная сеть остаётся доступна.
- **Выкл** — туннель остановлен, обычный интернет напрямую.
- **Авто** — выбранные сайты/сервисы через VPN, остальное напрямую.
- Импорт `.conf` AmneziaWG/WireGuard, несколько профилей, основной и порядок резервных.
- Живая проверка HTTPS через VPN на двух независимых адресах. После трёх неудачных
  циклов — освобождение туннеля и проверка следующего профиля.
- Кандидаты проверяются без установки маршрутов. При недоступности всех серверов
  интернет остаётся напрямую; повторы каждые 10 секунд после окончания предыдущего цикла.
- Трей, автозапуск интерфейса, экспорт/импорт правил, Geo-Aggregator, восстановление сети.
- Подсказки сервисов по части названия (`dis` → Discord), тёмный выбор файлов .conf
  и подтверждение удаления профиля с безопасной кнопкой «Отмена» по умолчанию.
- Пользовательские настройки защищены DPAPI CurrentUser. Служебные — DPAPI LocalMachine
  в каталоге с ACL только SYSTEM/Administrators. Управление службой — через named pipe
  с доступом установившему пользователю, SYSTEM и администраторам.

## Установка

Основной установщик: `artifacts/RED_ROUTE-0.1.14-Setup.exe` — тёмное окно WPF,
непрерывный прогресс от Windows Installer и завершение в том же окне.
Для автоматизированной установки также доступен `artifacts/RED_ROUTE-0.1.14-win-x64.msi`.
Запустить установщик, разрешить UAC, затем открыть RED_ROUTE из меню «Пуск».
Мастер показывает приветствие и экран успешного завершения. Кнопка «Готово»
закрывает установщик и открывает приложение, если отмечен флажок запуска.
При отключённом UAC Windows не показывает запрос повышения прав.
На вкладке «Профили» добавить `.conf`; первым расположить основной сервер.
Добавить сайты на главном экране и выбрать «Авто» или «Вкл».
.NET и отдельный клиент Amnezia устанавливать не нужно: runtime и ядро входят в пакет.

Служба работает отдельно от окна. Крестик прячет окно в трей; «Выключить VPN и выйти»
останавливает VPN. После перезагрузки служба восстанавливает последний сохранённый режим.
Сам интерфейс запускается при входе, если включён соответствующий флажок.

## Обновления и каталог

Под номером версии появляется кнопка обновления, когда на GitHub есть новый стабильный
релиз. Проверка выполняется при запуске, каждые 6 часов и вручную в разделе «Помощь».
Загрузка показывает прогресс; размер и SHA-256 проверяются перед запуском.
Обновление запускает полный установщик с запросом UAC, заменяет программу и службу,
сохраняя профили и правила. Во время установки VPN временно переподключается.
Скачивание и проверка обновления прав администратора не требуют.

Нажатие на пустое поле сайта открывает весь каталог сервисов и доменов. Ввод части
названия или домена фильтрует список; уже добавленные позиции остаются видимыми.
Категория 18+ и её домены исключены из подсказок, включая кеш и обновления базы.
Встроенная база содержит 311 сервисов Geo-Aggregator, домены и IP-сети.

Публикация: изменить Version в Directory.Build.props, собрать и отправить тег `vX.Y.Z`.
GitHub Actions публикует установщик, MSI, контрольную сумму и исходники ядра.
Результаты проверки: [docs/TEST-REPORT-0.1.10.md](docs/TEST-REPORT-0.1.10.md).

## Разрешения и восстановление

Администратор нужен при установке/обновлении/удалении. Обычная работа — без UAC.
«Восстановить обычный интернет» запоминает «Выкл», останавливает собственное ядро,
освобождает его TUN/маршруты и очищает DNS-кеш. Профили и правила сохраняются.
Физические интерфейсы, настройки роутера и чужие VPN не сбрасываются.
Если служба недоступна, тот же обработчик запускает установленную службу с
`--recover` с UAC. Независимый ярлык: «RED_ROUTE — восстановить интернет».

## Сборка

Нужен Windows x64, .NET SDK 10.0 и Go 1.26.10. Поместить архив Go в `.tools/go1.26.10` (go/bin внутри)
либо передать путь в `scripts/build-engine.ps1 -Go ...`.

```powershell
./scripts/build.ps1
# После сборки ядра:
./scripts/build.ps1 -SkipEngine
# Проверки, не включающие VPN:
dotnet run --project tests/RedRoute.Tests -c Release
./src/RedRoute.App/bin/Release/net10.0-windows/RED_ROUTE.exe --smoke-test
```

WiX 6.0.2 автоматически восстанавливается как MSBuild SDK. Ядро собирается из
закреплённого commit; происхождение и лицензии см. [THIRD-PARTY.md](THIRD-PARTY.md).
Автоматизация GitHub собирает MSI и сохраняет артефакт при push, pull request или теге `v*`.

## Подготовка релиза 0.1.14

Полный сборочный прогон включает модульные проверки, матрицу отказов, защищённое
хранилище, повреждённые IPC/HTTP-данные и локальный клиент-серверный стенд настоящего
ядра. Стенд проверяет WG/AWG, расширенные параметры AWG, IPv4/IPv6 и маршрутизацию
доменных правил без системного TUN и без пользовательских конфигов.

```powershell
dotnet run --project tests/RedRoute.Tests -c Release -- --native-lab
./scripts/test-ui.ps1
```

Проверки интерфейса имеют ограничение по времени, а намеренная ошибка smoke-теста
обязана вернуть ненулевой код. Подробности и оставшиеся проверки перед 1.0:
[docs/TEST-REPORT-0.1.14.md](docs/TEST-REPORT-0.1.14.md).

Для сравнения проблемных сайтов с текущими правилами есть отдельный диагностический
режим, который не переключает VPN и не выводит ключи/адреса серверов:

```powershell
dotnet run --project tools/RedRoute.Probe -c Release -- --site-diagnostics
```

`--site-compare` временно выключает только RED_ROUTE и восстанавливает прежний режим
и пользовательские настройки в `finally`. `--live-acceptance` и
`--cached-dns-regression` предназначены для разработчика: меняют тестовые настройки
службы и принудительно завершают только проверенные установленные процессы RED_ROUTE.

## История: статус 0.1.8

Исправлены лишние перезапуски при изменении имени/резервов, устаревшее состояние после
временной ошибки проверки и потеря уже выданных FakeIP-адресов при аварии ядра.
Фоновая база не меняет выбранный режим и не может включить VPN после восстановления.
Служба автоматически перезапускается после аварии; последние события соединения
сохраняются в защищённом служебном каталоге. Технический DNS-кеш тоже хранится там;
он не включается в диагностический отчёт и не содержит ключей профиля.

Устранена DNS-рекурсия Windows: DNS физического адаптера определяется до создания
туннеля и используется напрямую с привязкой к этому адаптеру. В локальном сравнении
задержка запросов вне списка сократилась с 5,2–5,4 с до 0,2–0,4 с; после установки
контрольный прогон Auto дал 0,47–0,71 с при 0,56–0,69 с с выключенным VPN.
Это замеры открытия HTTPS, а не пропускной способности канала.

Проверены 84 сценария C#, 3 Go-теста, схема ядра и WPF-интерфейс. Живой прогон
проверил режимы, недоступный основной, отказ всех профилей, аварию ядра/службы,
быстрые команды, восстановление и сохранение кешированного DNS после аварии.
Результаты и пределы проверки: [docs/TEST-REPORT-0.1.8.md](docs/TEST-REPORT-0.1.8.md).
Windows 10, dual-stack, независимые физические серверы, сон и смена физической сети
требуют отдельной среды; эти сценарии не объявляются пройденными.

## Ограничения

- Проверка потери связи занимает до трёх циклов (10 секунд между циклами, HTTPS timeout
  5 секунд). В этот промежуток уже направленные в VPN соединения могут ждать/обрываться;
  после обнаружения ошибки туннель снимается. Мгновенный бесшовный перенос TCP-сессий не заявляется.
- С рабочего резерва не прыгаем обратно на основной; новое включение начинает с основного.
- DNS приложения сохраняет доменные имена через FakeIP. Защищённый DNS браузера + ECH
  может скрыть домен; тогда доступны IP-правила, остальное идёт напрямую в «Авто».
- Конфиги с несколькими Peer, скриптами PostUp/PostDown, неизвестными полями и невалидными
  ключами отклоняются. Импорт поддерживаемых полей AWG 1/1.5/2/3 отражён в парсере.
- Пакет x64 и без цифровой подписи. ARM64/x86 не являются проверенными целями.
- Установивший пользователь назначается владельцем управления; многопользовательский
  интерфейс и смена владельца через UI пока не реализованы.

В отчёт не входят ключи, исходные конфиги, список посещённых сайтов или содержимое трафика.
Имена профилей и события соединения входят в отчёт, который пользователь сохраняет сам.
